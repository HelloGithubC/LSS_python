# Compact covariance sample storage

`XismuCovarianceIO` saves covariance samples in a compact, versioned binary
file and loads them as a one-dimensional NumPy object array of `xismu` objects
and `None` entries. The serial and MPI covariance-source scripts write this
format directly; the reader accepts only this compact format.

## Requirements

Use the project's Python environment with `LSS_python`, NumPy and joblib
installed. Loading uses Python's pickle-based joblib serialization: **only load
files from trusted sources**, because loading an untrusted file can execute
arbitrary code.

## Workflow

1. Obtain a one-dimensional sequence of `xismu` objects and optional `None`
   entries from a covariance calculation or by loading a compact file.
2. Choose `covariance_type="jk"` for jackknife samples or
   `covariance_type="subsample"` for subsamples. Save the sequence with
   `XismuCovarianceIO.save(filename, samples, covariance_type)`.
3. Read the compact file with `XismuCovarianceIO.load(filename)`. The result
   preserves sample order and `None` entries and can be passed to existing code
   that consumes the original object array.

The file stores one copy of the common `S` and `Mu` arrays. It stores each
sample's normalized `DD` and `DR`, plus each `RR` for jackknife; for subsamples
it stores one shared `RR`. Normalization factors, cached `xis`, weight metadata
and other object attributes are retained. Loading restores the stored object
state without normalizing the arrays again or modifying the first bin. This
format reduces storage duplication without reducing floating-point precision;
it does not promise reduced memory usage after loading.

Saving requires at least one non-`None` sample, matching array dimensions and
identical coordinates across all valid samples. Subsamples must also have
identical `RR` and `RR` normalization factors. Invalid input, unsupported
format versions and malformed compact files raise an error. An existing output
path is rejected rather than overwritten unless `overwrite=True` is passed.
`load` rejects legacy object arrays; convert them with the migration command
below. Only trusted pickle files should be loaded.

## Example

The following example reads a compact jackknife result and writes a new
compact file. Replace both absolute paths with paths appropriate for your
system. The destination must not already exist, and its parent directory must
already exist.

```python
from LSS_python.xismu import XismuCovarianceIO

source = "/absolute/path/to/compact_jk.pkl"
destination = "/absolute/path/to/new_jk_compact.pkl"

samples = XismuCovarianceIO.load(source)
XismuCovarianceIO.save(destination, samples, covariance_type="jk")
restored_samples = XismuCovarianceIO.load(destination)
```

Run this code in the project's configured Python environment, for example as
`python example.py` after saving the snippet in `example.py`. For a subsample
result, use `covariance_type="subsample"` and a distinct destination.

The input is the specified existing compact file. The output is the
single binary file at the specified destination, containing the versioned
compact representation. The variables `samples` and `restored_samples` are
in-memory arrays; the API does not intentionally create intermediate files,
logs, standard-output files, caches or checkpoints. Standard output and error
remain attached to the calling process unless the caller redirects them. The
example does not delete input or output files. Paths in this example are
placeholders, and no example file is provided or generated by this document.

## Covariance-source calculation scripts

`bin/cal_cov_source_tpcf` and `bin/cal_cov_source_tpcf_mpi` produce the compact
file at `--tpcf_filename` (default `tpCF_temp.pkl` in the working directory).
Both take data and random `.npy` catalogs, a box size, a grid count and `jk`
or `subsample`; the MPI command is launched with `mpiexec` and additionally
requires mpi4py and an MPI runtime. For example:

```sh
python bin/cal_cov_source_tpcf data.npy random.npy 2500 10 jk -n 8 \
  -tpcf /absolute/path/to/covariance.pkl -rr /absolute/path/to/rr.pkl
mpiexec -n 4 python bin/cal_cov_source_tpcf_mpi data.npy random.npy 2500 10 subsample -n 8 \
  -tpcf /absolute/path/to/subsamples.pkl -rr /absolute/path/to/sub_rr.pkl
```

Each command reads the catalogs, computes or reuses the separately stored RR
cache, counts the other pairs and writes the sample file. Load that file with
`XismuCovarianceIO.load`, not `joblib.load`. The bin settings, thread count,
weights, correction and RR-cache options are described by each command's
`--help`. An existing output is checked as compact and skipped unless `-f` is
provided. With `-f`, the compact output is written to a unique directory
`.<output-name>.write-<random>/result.pkl` beside the resolved output and then
replaces it; the temporary directory is removed after completion or handled
failure. An RR cache may be created or replaced using `-frr`, independently of
the sample output. Relative paths are resolved from the working directory.
The commands create no persistent logs or checkpoints; stdout and stderr can
be redirected by the caller or scheduler. Corrfunc may create temporary bin
files in the process temporary directory. These example paths are illustrative
and the examples have not been run.

## Convert a legacy file in place

The executable `bin/migrate_xismu_covariance` converts one existing legacy
one-dimensional joblib array to the compact format and **replaces the input
file**. Specify the actual covariance method explicitly:

```sh
python bin/migrate_xismu_covariance /absolute/path/to/jackknife.pkl --covariance-type jk
python bin/migrate_xismu_covariance /absolute/path/to/subsamples.pkl --covariance-type subsample
```

The script requires the same Python environment, NumPy and joblib as above.
With no arguments it prints help. It reads the legacy samples, writes a compact
file in a uniquely named temporary directory on the input file's filesystem,
reloads and compares sample attributes, then atomically replaces the input.
It reports the original and final byte counts on standard output. Errors go to
standard error and cause a nonzero exit status. Existing valid compact files
are reported as already converted and skipped successfully without modification;
unsupported versions and malformed files still cause an error. The script
checks the input file's identity, size and timestamps
immediately before replacement and refuses a detected concurrent change.

For an input `/absolute/directory/name.pkl`, the only final output is that
same path in compact format. The intermediate path is
`/absolute/directory/.name.pkl.compact-<random>/result.pkl`; the temporary
directory and file are removed on success or a handled failure. No backup,
checkpoint, log or standard-output/error file is created by the script. Its
parent directory must be writable. Symbolic links are followed and retained;
the resolved target is replaced. Permission bits are preserved, but replacement
creates a new inode: other hard links still refer to the old inode, and file
ownership and other inode metadata are not preserved. The temporary file may
remain if the process is forcibly terminated or the machine loses power.
The examples above are illustrative and have not been run on those paths.
